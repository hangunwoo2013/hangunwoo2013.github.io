# B-ROUTE 1.92 — GitHub, 프로젝트 협업 및 경로 공유

## 1. 버전 정책

- 1.92 이후 1.9x: 정식 배포 전 개발·오류 수정
- 2.0 Beta Test: 실제 서비스 기반의 비공개 베타
- 2.0: 피드백 반영 및 검증 후 정식 공개

## 2. 프로젝트

로그인한 사용자는 프로젝트를 만들고 구성원을 초대할 수 있습니다.

| 권한 | 프로젝트 정보 수정 | 경로 조회 | 경로 수정·추가 | 구성원 관리 |
|---|---:|---:|---:|---:|
| owner | O | O | O | O |
| editor | X | O | O | X |
| viewer | X | O | X | X |

현재 기본 한도:
- 사용자당 프로젝트 최대 5개
- 프로젝트당 구성원 최대 10명(소유자 포함)
- 프로젝트당 경로 최대 100개
- 프로젝트당 대기 초대 최대 10개
- 경로 버전 이력 및 복구

모든 권한 검사는 화면뿐 아니라 서버 API에서도 수행합니다. 뷰어는 원본 경로를 수정할 수 없습니다. 뷰어가 편집하려면 읽기 전용 경로를 자기 경로로 복사해야 합니다.

## 3. 계정 공급자

Google, Naver OIDC, Microsoft Identity Platform 로그인을 지원하는 구조입니다.

- Google 계정은 글로벌 총괄자 지정에도 사용할 수 있습니다.
- Naver OIDC의 `sub`를 앱별 고유 식별자로 사용합니다.
- Microsoft는 `tid`와 `oid`를 우선하여 식별합니다.
- 이메일 주소는 표시/초대 대상 메모에만 사용하고 권한 확인 키로 사용하지 않습니다.
- 동일 이메일이어도 Google/Naver/Microsoft 로그인은 기본적으로 서로 다른 B-ROUTE 계정입니다. 계정 연결/병합은 아직 구현하지 않았습니다.

Microsoft 로그인에서 개인 Outlook/Hotmail 계정을 받으려면 Entra 앱 등록에서 개인 Microsoft 계정을 포함하는 지원 계정 유형을 선택해야 합니다. `MICROSOFT_TENANT=common`만 입력한다고 앱 등록 유형이 자동 변경되지는 않습니다.

## 4. 초대 방식의 중요한 제한

현재 프로젝트 초대는 서버가 7일 유효·1회 사용의 임의 토큰 링크를 생성하고, 소유자가 직접 복사해 전달하는 방식입니다. 자동 이메일 발송은 구현되어 있지 않습니다.

초대 폼의 이메일은 전달 대상 표시용입니다. Naver/Microsoft 프로필 이메일을 검증된 권한 증명으로 간주하지 않기 때문에, 초대 링크를 가진 사람이 Google/Naver/Microsoft 지원 계정으로 수락할 수 있습니다. 따라서 링크는 지정한 사람에게만 전달하고 잘못 전달했으면 수락 전에 취소해야 합니다. 초대 이메일과 로그인 계정 이메일의 자동 일치 확인은 현재 기능이 아닙니다.

## 5. 일반 경로 공유와 프로젝트 경로 공유

- 일반 공유: 작성자가 경로 링크를 발급하고 받는 사람은 읽기 전용으로 확인합니다.
- 프로젝트 공유: 프로젝트 owner/editor가 특정 프로젝트 경로를 읽기 전용 링크로 발급합니다.
- 공유 링크는 만료일 및 열람 횟수 제한을 적용하고 소유자가 취소할 수 있습니다.
- 기본 공유는 7일, 최대 열람 100회이며 설정 범위는 1~30일, 1~500회입니다.
- 기본 저장 한도는 계정당 클라우드 1GB, 파일 하나 최대 5MB입니다. 실제 클라우드 보관은 PostgreSQL과 COS를 연결한 뒤 활성화됩니다.

## 6. 동일 주소 업데이트

GitHub Actions에서 기존 Cloud Run 서비스로 새 Revision을 배포합니다. 서비스 URL은 유지되고 트래픽이 새 Revision으로 전환됩니다. 배포 문제 발생 시 수동 rollback Workflow에서 이전 Revision으로 트래픽을 돌립니다. 상세 설정은 `GITHUB-SETUP-1.92.md` 및 `COST-AND-URL-MIGRATION-1.92.md`를 참조하세요.
