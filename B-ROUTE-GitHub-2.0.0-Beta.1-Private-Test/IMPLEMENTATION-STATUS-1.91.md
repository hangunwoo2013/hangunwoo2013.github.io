# B-ROUTE 1.91 구현 현황

## 버전 정책

- 1.91, 1.92, 1.93…: 비공개 베타 전 개발 버전
- 2.0 Beta Test: 실제 서비스 환경의 비공개 베타
- 2.0: 피드백 수정 및 최종 검증 후 정식 공개 버전

## 1.91 완료

- TAGO TrainInfo 작업명 대소문자 수정: `GetCtyCodeList`, `GetCtyAcctoTrainSttnList`, `GetStrtpntAlocFndTrainInfo`
- TAGO `getSttnThrghRouteList` 서비스 루트 수정: `BusSttnInfoInqireService`
- 정류소 경유노선 요청 파라미터 `nodeid` 정확히 적용 (`nodeId`가 아님)
- 정류소 경유노선 응답을 공통 버스 노선 구조로 정규화
- TAGO 주변 정류소 API 500m 고정 범위 반영 및 지원하지 않는 upstream `radius` 인자 미전송
- `resultCode=03` 정상 무자료 응답 처리
- 서비스별 인증·호출량·IP 오류 매핑 보강
- 총괄자 API 검사 기능을 개별 작업으로 확장
  - 버스 도시코드 및 노선 목록
  - 버스 노선별 경유정류장
  - TAGO 정류소별 경유노선
  - TAGO 실시간 도착정보
  - 철도 도시코드
  - 철도역 목록
  - 출발·도착 열차 시간표
- API 연결 검사에서 서비스명·오퍼레이션·원본 건수·정규화 건수 표시
- 서비스키 원문 응답 차단 및 총괄자 전용 검사 권한 유지
- 테스트 파일을 1.91 이름으로 정리

## 구현상 한계

- 실제 data.go.kr 실서버 호출은 API 키 및 상품별 활용신청 승인 전까지 검증하지 않았습니다.
- 공공데이터포털 계정과 키가 있어도 각 API 상품별 활용신청/승인이 필요합니다.
- 응답 성공은 데이터 범위 완전성이나 GTFS 그래프 적재를 보증하지 않습니다.
- TAGO 실시간 도착 및 OD 열차 조회는 보조 데이터입니다. 다중 환승 경로는 GTFS 정적 네트워크와 환승 그래프 기반입니다.
- 실제 공급원별 pagination, 지역 커버리지, 실제 데이터 ID 매핑은 1.92 이후 지속 검증해야 합니다.
- EdgeOne 배포 테스트 및 실 운영 자격증명 검사는 수행하지 않았습니다.
