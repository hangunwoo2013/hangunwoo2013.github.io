# B-ROUTE Local 1.5 — Production Foundation

## 목표 변경
- 1.4의 화면 시연 중심 목표에서 정식 배포 직전 비공개 베타를 위한 서비스 기반 구축으로 방향을 변경했습니다.
- `?demo=1`은 QA용 가상 데이터 모드로 남기며, 실제 운영/베타 경로 안내와 혼동하지 않도록 했습니다.

## 주요 변경
- PostgreSQL 운영 연결 지원(PSYCOPG 3)과 SQLite 로컬 개발 분리
- 운영 환경에서 영구 DB가 없으면 핵심 영구 데이터 작업을 503으로 fail-closed
- users / cloud_files / app_settings / admin_audit_logs / data_releases 스키마 추가
- 기존 feedback 테이블을 사용자 식별, 상태, 답변, 처리시각을 포함하도록 마이그레이션
- COS 서버 측 업로드·서명 다운로드 URL·삭제 API 추가
- 계정별 기본 1,000MB 저장량과 단일 파일 5MB 제한
- 사용자 문의 서버 접수 및 본인 문의 내역/총괄자 답변 확인
- 총괄자 문의 상태 변경 및 답변 저장
- 총괄자 일반 설정 수정, 사유 기록, 감사 로그 및 설정 롤백
- 관리판 확장: 연결 준비상태, 설정 편집, 문의 처리, 변경 이력/복구
- 프런트엔드 저장한 `.broute` 경로를 클라우드 보관함으로 업로드하는 흐름 추가
- 실제 배포 환경 GTFS 업로드 한도를 EdgeOne 6MB 요청 본문 제한에 맞춰 5MB로 제한
- 서비스 워커 캐시 버전 `1.5`로 갱신

## 보안
- Google ID token은 백엔드에서 검증
- API/COS 비밀값은 환경변수에서만 읽고 API 응답으로 반환하지 않음
- 클라우드 파일 object key는 사용자별 비식별 prefix + 랜덤 ID
- 다운로드·삭제 시 로그인 사용자와 파일 소유자를 대조
- 운영 설정 allowlist 적용, 비밀값은 관리판에서 변경 불가
- 운영 환경 SQLite 사용을 영구 저장으로 오인하지 않도록 제한

## 제한 및 미완성
- PostgreSQL/COS 실제 자격 증명이 없어 외부 인프라 연동은 실기 테스트하지 않았습니다.
- COS SDK는 의존성에 추가했지만 실제 버킷 요청 테스트는 수행하지 않았습니다.
- Google OAuth 실계정 인증은 실기 테스트하지 않았습니다.
- EdgeOne 배포 테스트는 수행하지 않았습니다.
- 5MB 초과 GTFS의 COS staging 및 배치 import는 다음 개발 단계입니다.
- 전국 교통정보 공급 범위, 실제 시간표 품질, 데이터 릴리스 자동화는 다음 단계입니다.
- `BETA_RELEASE_APPROVED` 기본값은 false이며 실제 비공개 베타 개시를 승인하지 않습니다.

- 기기 자동 저장을 IndexedDB 기반으로 변경하고 기존 localStorage 경로를 첫 실행 때 병합 이전
- IndexedDB 미지원/오류 시 localStorage 예비 저장소로 전환하고 화면에 상태 안내
- `.broute` 클라우드 업로드 시 형식·스키마·좌표 검증을 서버에서 수행
- COS 객체 저장 후 DB 메타데이터 기록에 실패하면 객체 삭제를 보상 시도
- 관리자 상태 화면에 COS Secret 등록 여부와 실제 버킷 연결 검증이 다름을 명시
